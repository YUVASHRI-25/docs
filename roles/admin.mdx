HR admins use Resume Insight to perform thorough, structured evaluations of individual candidates. Rather than switching between multiple tools to check a candidate's resume quality, coding activity, and competitive programming profile, the Admin dashboard brings all of that together in a single request. You upload the resume file, optionally pass the candidate's GitHub, LeetCode, and CodeChef usernames, and receive a consolidated report covering every dimension of the candidate's technical profile.

## Analyzing a Candidate

The `POST /analyze_all` endpoint is your primary tool as an HR admin. It accepts one resume file plus optional query parameters for GitHub, LeetCode, and CodeChef usernames. You get back a single JSON response containing every platform's data in clearly labeled sections.

**Full curl example — resume + all three platforms:**

```bash
curl -X POST "http://localhost:8000/analyze_all?github=alexjohnson&leetcode=alex_lc&codechef=alex_cc" \
  -H "Authorization: Bearer <your_admin_token>" \
  -F "file=@/path/to/candidate_resume.pdf"
```

**Query parameters:**

<ParamField query="github" type="string">
  GitHub username or full profile URL (e.g., `alexjohnson` or `https://github.com/alexjohnson`). The system extracts the username automatically from a URL.
</ParamField>

<ParamField query="leetcode" type="string">
  LeetCode username (e.g., `alex_lc`).
</ParamField>

<ParamField query="codechef" type="string">
  CodeChef username (e.g., `alex_cc`).
</ParamField>

<ParamField query="token" type="string">
  A personal GitHub access token. Use this if the server's default token is hitting GitHub's rate limits. See the [GitHub Analysis](#github-analysis) section for details.
</ParamField>

## GitHub Analysis

When you pass a `github` username, Resume Insight uses the GitHub GraphQL API and REST API to fetch the candidate's public development activity. The following metrics are returned inside `github.github_metrics`:

<ResponseField name="total_original_repos" type="number">
  Number of repositories the candidate created themselves (not forks).
</ResponseField>

<ResponseField name="total_forked_repos" type="number">
  Number of repositories forked from other projects.
</ResponseField>

<ResponseField name="total_contributions_1yr" type="number">
  Total contributions (commits, PRs, issues, reviews) made in the past 12 months.
</ResponseField>

<ResponseField name="total_prs_submitted" type="number">
  Total number of pull requests the candidate has submitted across all public repositories.
</ResponseField>

<ResponseField name="prs_merged" type="number">
  How many of those pull requests were merged.
</ResponseField>

<ResponseField name="pr_acceptance_rate" type="number">
  Percentage of submitted PRs that were merged (`prs_merged / total_prs_submitted × 100`).
</ResponseField>

<ResponseField name="avg_pr_size_lines" type="number">
  Average number of lines changed (additions + deletions) across merged PRs.
</ResponseField>

<ResponseField name="avg_time_to_merge_days" type="number">
  Average number of days between PR creation and merge across all merged PRs.
</ResponseField>

<Tip>
  GitHub's API enforces rate limits. If you run many candidate evaluations in quick succession, pass the candidate's GitHub token (or a dedicated evaluation token) as the `?token=` query parameter in the request. This uses that token's rate limit allocation rather than the server's default token.
</Tip>

## LeetCode Analysis

When you pass a `leetcode` username, Resume Insight fetches the candidate's full submission stats and generates a performance analysis. The response contains three sections:

<Expandable title="profile — raw stats">

<ResponseField name="Username" type="string">
  The candidate's LeetCode username as returned by the API.
</ResponseField>

<ResponseField name="Total_Solved" type="string">
  Total number of problems the candidate has accepted.
</ResponseField>

<ResponseField name="Easy / Medium / Hard" type="string">
  Accepted problem count for each difficulty tier.
</ResponseField>

<ResponseField name="Ranking" type="number">
  The candidate's global ranking on LeetCode (lower is better).
</ResponseField>

<ResponseField name="Rating" type="number">
  The candidate's star rating on LeetCode (0–5).
</ResponseField>

<ResponseField name="Languages" type="array">
  List of programming languages the candidate has used to solve problems.
</ResponseField>

</Expandable>

<Expandable title="analysis — interpreted performance">

<ResponseField name="sentiment" type="string">
  `"positive"` (2000+ problems), `"neutral"` (500–1999), or `"negative"` (under 500).
</ResponseField>

<ResponseField name="reason" type="string">
  A plain-English summary of the candidate's standing, with specific suggestions if the sentiment is not positive.
</ResponseField>

<ResponseField name="metrics.problem_distribution" type="string">
  Percentage breakdown of easy/medium/hard problems as a formatted string.
</ResponseField>

<ResponseField name="metrics.difficulty_rating" type="number">
  Weighted average difficulty across all problems solved (Easy=1, Medium=2, Hard=3).
</ResponseField>

<ResponseField name="metrics.languages_used" type="number">
  Number of distinct languages the candidate has coded in.
</ResponseField>

</Expandable>

<Expandable title="activity_graph — submission calendar">

An array of daily submission counts covering the candidate's recent activity. Each entry has a `date` (ISO format) and a `count` representing the number of submissions made on that day. Use this to visualize consistency of practice over time.

</Expandable>

## CodeChef Analysis

When you pass a `codechef` username, Resume Insight scrapes the candidate's public CodeChef profile and returns the following data inside `codechef.profile`:

<ResponseField name="Rating" type="number">
  The candidate's current CodeChef rating (e.g., `1854`).
</ResponseField>

<ResponseField name="Star_Rating" type="string">
  Star tier corresponding to the rating, e.g., `"4★"` or `"3★"`.
</ResponseField>

<ResponseField name="Global_Rank" type="number">
  The candidate's rank among all CodeChef users worldwide.
</ResponseField>

<ResponseField name="Country_Rank" type="number">
  The candidate's rank within their country.
</ResponseField>

<ResponseField name="Badges" type="array">
  List of badges earned on CodeChef, such as `"Div. 2 Specialist"` or `"Problem Solver"`.
</ResponseField>

<ResponseField name="Total_Solved" type="number">
  Total number of problems the candidate has solved on CodeChef.
</ResponseField>

<ResponseField name="Learning_Paths" type="array">
  Structured learning paths the candidate has started or completed, each with a `name` and a `percentage` completion.
</ResponseField>

<ResponseField name="Practice_Paths" type="array">
  Practice problem sets the candidate has attempted, with names and completion percentages.
</ResponseField>

<Tabs>
  <Tab title="Strong Candidate Signals">
    When reviewing CodeChef data, look for:
    - **Rating ≥ 1800** — indicates consistent contest performance at the 4★ level or above
    - **Global Rank under 10,000** — places the candidate in the top tier of competitive programmers
    - **Total Solved > 200** — demonstrates sustained practice beyond contest participation
    - **Multiple learning path completions** — shows structured self-improvement
  </Tab>
